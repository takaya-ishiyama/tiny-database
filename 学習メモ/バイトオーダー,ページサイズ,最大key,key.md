### バイトオーダー

  整数を複数バイトで保存するときの、バイトの並べ方です。

  例えば 305419896 は16進数で 0x12345678 です。

  - Big-endian：12 34 56 78
  - Little-endian：78 56 34 12

  保存時と読み込み時で解釈が違うと、元の数値に戻せません。そのため「little-endianを使う」のように決めます。

  Rustなら次の部分に影響します。

  let bytes = value.to_le_bytes();
  let value = u32::from_le_bytes(bytes);

### ページサイズ

  DBがファイルを読み書き・管理するときの基本単位です。

  例えばページサイズを4 KiBにすると、ファイルを次のような箱の集まりとして扱いま
  す。

  DBファイル
  ├── Page 0: 4096 bytes
  ├── Page 1: 4096 bytes
  ├── Page 2: 4096 bytes
  └── ...

  レコードを1件ずつ適当に配置するのではなく、4 KiBのページへ詰めて管理します。
  index.html ではすでに「4 KiB固定長ページ」を初期案にしています。

### 最大key/value長

  保存できるキーと値の大きさの上限です。

  key   = "user:123"       → 8 bytes
  value = "{...user...}"   → 250 bytes

  例えば以下のようなルールを決めます。

  key   は最大 1024 bytes
  value は最大 3000 bytes

  上限が必要なのは、主に以下の理由です。

  - 1件のデータがページへ収まるか判断するため
  - 壊れたファイルを読んで巨大なメモリを確保する事故を防ぐため
  - put() が何を受け付けるか明確にするため

  日本語の文字数ではなく、UTF-8などに変換した後の「バイト数」で考えます。
